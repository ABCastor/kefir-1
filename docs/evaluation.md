# Evaluation

Kefir 1 was measured in four ways: text likelihood for the base checkpoints, held-out assistant NLL for the SFT
checkpoints, a small frozen chat suite, `kefir-bench/1`, and a zero-shot comparison of Kefir 1 Base and Kefir 1
with six small open models in lm-evaluation-harness 0.4.13 (adapter, settings and tables in
[results/benchmarks.md](../results/benchmarks.md)). The numbers measured in this repository are in
[`results/`](../results/README.md). There is no aggregate score, no release threshold and no automatic winner.

## Base model: text likelihood

`kefir evaluate text --weights W.safetensors --dataset-dir DIR [--validation-blocks N] [--thematic-panels [DIR]]`

Options: `--validation-blocks N` (default 1), `--thematic-panels` (the bundled panels, or a panel directory),
`--device` (default `cpu`), `--precision fp32|fp16|bf16` (default `fp32`) and `--microbatch-size N` (default 1).

- **Validation loss.** Mean cross-entropy (nats per target) over the first `N` held-out blocks of a prepared
  schema-v2 corpus whose manifest carries the pinned tokenizer hash. During pretraining, validation used
  2,097,152 targets per event, in BF16.
- **Thematic panels.** Twelve frozen panels (`src/kefir/assets/thematic_panels_v1/`: arts and literature, biology
  and health, conversation and emotions, general prose, geography, history and culture, language and grammar,
  physical world, practical life, society and economics, spatial reasoning, verbal reasoning), each up to 32
  windows of 2,048 tokens assigned by keywords. NLL is summed per panel and divided by its target count; the
  weighted value pools all panels. They show where likelihood moves; they are not task accuracy, and their
  overlap with the training corpus was not ruled out.
- **Shared-text bits per byte** on 384 held-out documents and a paired document bootstrap for the change between
  checkpoints (reported in `results/`; this analysis was run outside this repository's CLI). The interval covers
  document resampling only, not training seeds.
- **Behaviour probes** (facts, grammar, arithmetic, capitals, reversal pairs, free generations ending with EOD):
  small hand-written diagnostics scored by log-probability of supplied answer candidates, reported in
  `results/data/pretrain_probes.csv`. The probe items are not part of this repository.

## SFT model: held-out assistant NLL

Mean NLL over every assistant target (text and its EOD) of the 512 held-out validation conversations, over the full
vocabulary, with no router auxiliary loss: the sum of target NLLs divided by the target count (364,453), not a mean
of per-conversation means. The training loop measures it at every observation; `kefir evaluate chat --validation
rows.jsonl` measures it for saved weights. The [selected conversation view](https://huggingface.co/datasets/abcastor/kefir-1-sft-conversations) has a separate validation split. In the [labelled SFT pool](https://huggingface.co/datasets/abcastor/kefir-1-sft-labelled-pool), the corresponding rows have `membership == "validation"`.

## The frozen chat suite `kefir-bench/1`

1,022 cases in three splits, fixed by SHA-256 in `src/kefir/bench/data/manifest.json`:

| Category | dev | test (confirmation) | reserve | What it measures |
|---|---:|---:|---:|---|
| grammar | 64 | 128 | 64 | BLiMP minimal pairs, 8 paradigms: the grammatical sentence gets a higher raw log-probability |
| knowledge | 62 | 128 | 64 | short factual answers: ARC-Easy questions with their options (dev 30) and PopQA capital questions (dev 32) |
| instructions | 32 | 64 | 32 | authored tasks with checkable constraints (exact text, required or forbidden words, ending, letter case, line and bullet formats) |
| context | 48 | 96 | 48 | authored pairs (reading, fiction, examples, dialogue) where the answer depends on supplied context |
| reasoning | 32 | 64 | 32 | authored verbal, spatial and arithmetic problems in natural language |
| stopping | 16 | 32 | 16 | short requests where the model should end its reply itself |

Only the **development split (254 cases)** has ever been evaluated, and only it may be used to compare recipes.
The confirmation and reserve splits are packaged but untouched; `kefir evaluate chat` refuses them without
`--confirm-held-out-split`. Authored cases are held-out instances, but task mechanisms and some templates repeat
across splits. Overlap of public items with the pretraining or SFT data was not checked.

### Rebuilding the suite

The authored cases are generated by code (`src/kefir/bench/authored.py`). The public items are not shipped: they are
selected deterministically from upstream files pinned by URL and SHA-256 in
`src/kefir/bench/data/source-manifest.json` (BLiMP, CC BY 4.0; ARC-Easy, CC BY-SA 4.0; PopQA, MIT). Reading the ARC
Parquet files needs the `bench` extra (`pyarrow`).

```bash
pip install -e ".[bench]"     # with uv: uv sync --locked --extra bench
kefir bench build --cache cache/bench --output bench/kefir-bench-1 --download
```

`--download` fetches missing upstream files into the cache; without it the build uses only the cache and fails if
a file is missing. Every downloaded or cached file is checked against its hash, each public selection file against
its pinned hash, and the assembled `dev/test/reserve.jsonl` against the frozen manifest; any difference is an
error, so a successful build is exactly the suite used for the results. The output directory must not exist; it
appears only when the build succeeds, so a failed build can be retried as is.

### Running it

```bash
kefir evaluate chat --weights W.safetensors --benchmark bench/kefir-bench-1 --output eval/run-dev \
    [--validation validation-tokens.jsonl] [--device cuda --precision fp16]
```

Options: `--split dev|test|reserve` (default `dev`; the other two also need `--confirm-held-out-split`),
`--validation ROWS` (held-out token rows from `kefir sft render`, for the assistant NLL), `--device` (default
`cpu`), `--precision fp32|fp16` (default `fp32`; `fp16` needs a CUDA device and is refused elsewhere) and
`--trusted-state` (read a trainer state you trust instead of `.safetensors`). `--output` must be a new directory; it
is refused before any work if it exists and appears only when the evaluation succeeds.

Every prompt is rendered from the case's messages with the training renderer (Renderer C). Before inference every case is admitted: prompt plus output allowance must fit 2,048 tokens, otherwise the run
stops (no truncation, no dropped case). Generation is greedy, over ordinary text IDs plus EOD; a reply ends at EOD
(`native_end`) or at the case's output cap (`output_cap`).

The output directory holds `responses.jsonl` (text, termination, token counts and the likelihoods below),
`scored.jsonl` (per-case scores), `metrics.json` (category statistics, raw retention, validation NLL, runtime
receipt, weights hash, split) and, for the `dev` split only, `raw-retention.json` (raw retention is defined on the
development knowledge cases).

### How scores are computed

Scoring is a pure function of the case and the response (`src/kefir/bench/scoring.py`):

- **BLiMP /64**: credit 1 when the grammatical sentence has the higher log-probability after a document start (0.5
  on a tie). No chat formatting.
- **ARC raw /30**: each answer option is scored by its total log-probability as a continuation of
  `Question: <question>\nAnswer:` after a document start; credit when the gold option is highest (split on ties).
  `arc_norm` divides by the option's character length instead.
- **Instruction constraints /36**: the individual checkable constraints met across the 32 instruction tasks; each
  constraint passes only on a nonempty reply.
- **Exact match** (knowledge, context, reasoning): the reply, stripped and case-folded, equals one of the gold
  answers. This is a lower bound: verbose or partly correct answers score 0. Context cases also report pairs with
  both members correct.
- **Stopping /16**: replies to the dedicated stopping cases that end with the model's own EOD.
- **Raw-fact bits/byte (raw retention)**: for the 62 development knowledge cases, the log-probability of the
  canonical short answer (with a leading space, no EOD) after `Question: <question>\nAnswer:`, converted to bits per
  UTF-8 byte and pooled over cases. Lower means more probability on the reference answer; it is likelihood, not
  binary correctness.

The Open80 stopping counts use an additional 80-question panel whose prompts are not distributed. Those counts
cannot be reproduced with the public suite. They measure whether replies end, not answer quality.

### In-loop versus out-of-loop

During the Kefir 1 SFT runs the suite ran inside the training loop at each observation, with RNG state, buffers and
train mode restored afterwards. In this repository the loop measures only held-out NLL, and the suite runs as
`kefir evaluate chat` on the saved weights. The scoring code is byte-identical to the snapshot that produced the
results and the evaluator is equivalent on CPU (responses, scores and retention rows equal on a mixed case sample);
equality with the in-loop GPU numbers is argued from code identity, not re-measured.
